# Host probe composition and PREP-SMOKE-1 plan

## What changed

- Host no longer launches any process. `HostProbeProcessPort` (Host-owned) carries only data: the read-only probe argv (`--version`, `plugin list --json`), project directory, deadline and stdout/stderr bounds, plus the composition's executable identity.
- `receipts-cli::WorkspaceHostProbeRunner` is the admitted composition: an absolute path resolved to a canonical regular executable with its SHA-256, an explicit `ChildEnvPolicy`, and Workspace's bounded runner (cleared environment, process-group termination at the deadline, bounded capture). Non-zero exit, timeout, oversize stdout/stderr and cleanup failure are typed errors; partial output is never evidence. The old PATH-resolved `claude` spawn with direct-child-only cleanup is removed, not kept as a fallback.
- Executable drift detection: the runner re-resolves the canonical path, requires `lstat` to show a regular file, opens it non-blocking and requires the opened descriptor to be that same (device, inode) object, and stream-hashes it before and after every probe and on every identity query. Bytes different from the digest admitted at construction refuse with `ExecutableChanged` and the probe output is discarded, so an upgrade under an old runner, a replacement between the `--version` and plugin probes, and a replacement with identical reported output all refuse. Host also re-queries the identity after the last probe; any change leaves the fingerprint incomplete. This is pre/post pathname drift detection, not immutable binding: the process is still launched by pathname, so a swap-and-restore entirely inside one probe is not detected. Binding execution to the hashed object needs an execute-by-descriptor primitive the Workspace runner does not provide. A new validated runner explicitly admits new bytes.
- `HostObservationFingerprintV1` binds one observation to the executable path, content digest and value-free probe-policy description (provider, auth mode, admitted names), the SHA-256 and length of the `--version` and plugin-list output and of every settings source (or its typed absence/error), the host and the project root. Raw settings and probe bytes are not retained, and its `Debug` shows only lengths and digests.
- `HostCapabilityCacheEntryV1` couples one complete fingerprint, the mode override and the report selected from that same observation. It has no public constructor; only `refresh_host_capability_report` mints it, and only for a complete fingerprint with a selected report. Session activation always re-observes and reuses only when the fresh refresh minted an identical entry. A report and a fingerprint can no longer be supplied independently (`cached_report`/`cached_fingerprint` are removed); caller validity flags remain refused.

Synthetic controls (run on this Mac): admission refusals, exact stdout and policy-only child environment, non-zero/oversize refusals, timeout with descendant termination, unchanged-executable reuse, replacement after construction (including identical output), self-replacement during a probe, symlink substitution, replacement between probes, settings drift, entry reuse versus override/project/report/fingerprint substitution, incomplete-source refusal and no private-marker formatting. No installed host, global settings or provider was used.

## PREP-SMOKE-1 (prepared, NOT RUN)

Scope: one bounded, read-only installed-host probe. It needs its own concrete disposition before it is run. It is not the approved architectural D13.

1. Operator resolves the installed binary once and records it: `command -v claude`, then `realpath` of the result, `shasum -a 256 <realpath>` and `ls -l <realpath>`.
2. Create a temporary project: `mktemp -d /tmp/receipts-prep-smoke-1.XXXXXX`. No `.claude/` directory is created inside it.
3. Run a one-off test binary or harness that builds `WorkspaceHostProbeRunner::new(<realpath>, ChildEnvPolicy::new(Claude, Subscription))` and calls `refresh_host_capability_report` twice for `HostId::ClaudeCode` with that project root. Deadline 10 s per probe, 1 MiB stdout/stderr bounds, total cap 60 s.
4. Record, without payload logging: exit/typed outcome of each probe, byte lengths and SHA-256 of `--version` and plugin-list stdout, each settings source's typed result (path class only), `is_complete()`, whether each refresh minted a cache entry and whether the second permits reuse of the first, wall time, and absence of leftover child processes (`pgrep -f <realpath>` before and after).
5. Cleanup: `rm -rf` the temporary project only. Nothing is written to `~/.claude`, managed settings or plugin state. No model prompt and no provider request is made (`--version` and `plugin list --json` only).

Out of scope here: WorktreeCreate/WorktreeRemove hook smoke (needs the HI-W2 hook bridge and plugin), any `claude -p` or provider execution, and Codex probes.
