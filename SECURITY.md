# Security policy

Receipts is under active development. There is no supported production release or published security-support schedule yet. A development build should not be treated as a complete security boundary. See [README.md](README.md) for current limitations.

## Report a vulnerability privately

Use [GitHub private vulnerability reporting](https://github.com/01fe25bec239-collab/receipts/security/advisories/new). You can also open the repository's **Security → Advisories** page and select **Report a vulnerability**. This channel is enabled for this repository and sends the report privately to its maintainers.

Provide a summary, affected commit/version, impact, and the minimum reproduction needed for assessment. Use synthetic data and sanitize credentials and personal information. Include sensitive reproduction details only in the private report; do not create a public issue or PR containing an exploit, secret, or private user data.

Allow maintainers to assess the report and coordinate remediation and disclosure before publishing details. Response and remediation times depend on maintainer availability; no guaranteed timeline is currently offered. Reports do not authorize testing other users' repositories, systems, provider accounts, or services.

For ordinary bugs and feature requests without sensitive security details, use [GitHub issues](https://github.com/01fe25bec239-collab/receipts/issues).
